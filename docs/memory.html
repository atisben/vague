vague memory

How skills remember things across sessions and agents, and the CLI commands that make it happen. Branch feat/memory-ledger, 2026-11-11.

The one thing to remember: skills never touch memory files. They call the vague CLI, which appends one line to a file. The CLI also logs which memories each session used.

1. The big picture

Not shown, because it does not exist: no server, no daemon, no database, no embeddings, no lock files. The old stores (learnings.md, timeline.md, observations.md, principles.md, project.md, planning/) are gone.

2. One skill run, step by step

1Skill starts
The hook runs vague log-event, which appends a skill_start event.
Mechanical: the model does nothing.
→preamble runs
2Memory is shown
eval "$(vague context --shell --skill dev-develop)" prints the MEMORY block.
At most 1,500 tokens, ranked.
→model works
3Look up more
vague memory-search drift alert when the block isn't enough.
Example: dev-investigate.
→learns a fact
4Write it down
vague memory-log <key> "<text>", plus --global, --scratch or --about.
The model's choice, guided by the Memory guideline.
→days later
5Curate
/meta reads every memory with vague memory-search --scope all. It merges duplicates, promotes facts that hold in several projects, and fixes or forgets memories whose (files: …) no longer exist.
Nothing is deleted automatically.

save a fact about this projectvague memory-log ai-ml-tests-need-docker "Tests run only in the container…" --files Taskfile.yml --skill dev-shipOne line appended to memory.jsonl, scope = this repo
save a fact that holds in every repoadd --globalSame line, scope = global. It shows up in every project's MEMORY block, taking at most 1/3 of the budget.

With no words, it lists every memory, newest first. Each line prints as scope/key [skill] text (files: …). Default scope: this project plus global.

5. What the agent actually sees

A real MEMORY block from this repo, printed by the preamble. Lines are shortened here:

vague memory · scope atisben-vague · 11 memories
Scratch (shared by this scope's agents, last 7 days):
- [phase-4-status] verification running
Memories (most relevant first):
- [slug-fallback-cwd-subdir] Any fallback that derives project identity from cwd basename misidentifies…
- [verify-subagent-claims-independently] Re-running tests plus a manual end-to-end run caught a path…
- [telemetry-must-be-mechanical] Agent-discretionary end-of-skill logging never fires in practice…
- …

The block's budget is 1,500 tokens (6,000 characters):

  • scratch notes first, up to 300 tokens
  • full lines up to 1,200 tokens in total
  • key-only index lines up to 1,500
  • a final +N more: vague memory-search line

Memories are ranked by three rules, in this order:

  1. files you changed
  2. the same skill
  3. the newest first

A search prints one line per memory, as scope/key [skill] text (files: …), leaving out the parts that are empty. A real search from the same copy, with the text shortened:

$ vague memory-search --scope alma-ai_ml docker
alma-ai_ml/ai-ml-local-pytest-env  [dev-ship]  uv run pytest outside the container fails on missing settings env vars…
alma-ai_ml/ai-ml-tests-need-docker  [dev-review]  alma/ai_ml tests and mypy run only inside the container…  (files: Taskfile.yml)

These two lines are the duplicate that /meta should merge.

6. One line of memory

Every memory, observation and scratch note has these 8 fields:

{"ts":"2026-10-05T14:01:29Z", "scope":"alma-ai_ml", "key":"ai-ml-tests-need-docker", "kind":"learning",
 "text":"alma/ai_ml tests and mypy run only inside the customer-risk-train container…",
 "files":["Taskfile.yml"], "skill":"dev-ship", "status":"active"}
FieldMeaning
scopeWhich project it belongs to: the owner-repo slug from the git remote, the main checkout's folder name, or global
keyIts name. The same scope and key on a new line replace the old content.
kindlearning (a fact about a project) or observation (feedback about a skill)
files, skillUsed for ranking, and printed by memory-search. files lets /meta spot dead paths. skill tells it which skill an observation is about.
statusactive, forgotten, actioned or declined

7. Which project am I in?

Where the command runsScope
A git repo with an origin remoteowner-repo, e.g. atisben-vague. All worktrees share it.
A git repo without a remoteThe main checkout's folder name. Worktrees share it too.
A plain folder, e.g. ~/ObsidianThe folder name: Obsidian
$HOME or /None. memory-log refuses unless you pass --global.

8. Safety

  • Concurrent writers: each write is a single append of one line, so parallel agents never overwrite each other and no lock is needed.
  • Crashes: a half-written last line is skipped with a warning, and every other line still reads.
  • Privacy: events hold memory keys, never memory text or project file contents. Nothing leaves the machine. telemetry: off stops events, and memories are still written.
  • Direct edits: do not edit memory.jsonl by hand. Edits through the CLI are the ones monitoring can see.
